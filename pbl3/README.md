# PBL3 분석용 가상 데이터 (`pbl3` 스키마)

미션3 분석 4개 항목이 공통으로 쓰는 데이터입니다. 미션2 `public`은 건드리지 않고, 다음 과제에서 `public`으로 merge할 수 있도록 테이블·컬럼 이름을 `public`과 맞췄습니다.

## 실행

```bash
psql -U postgres -d swknu_db -f pbl3/reset_pbl3.sql

psql -d swknu_db -f pbl3/reset_pbl3.sql

```

- 약 30초. 끝에 `PBL3 verification passed.`와 건수·분포 요약이 출력됩니다.
- `public`에 의존하지 않습니다. 미션2 `reset.sql`을 다시 돌려도 영향이 없고, 빈 DB에서도 실행됩니다.
- 매번 두 스키마를 통째로 지우고 다시 만듭니다. 난수는 md5 해시 기반이라 **몇 번을 실행해도 같은 데이터**가 나옵니다.
- 기준일은 **2026-11-23**. 이후 회차 5개는 `SCHEDULED`로 남겨 예측·추천 시연에 씁니다.

| 파일 | 내용 |
|---|---|
| `10_pbl3_schema.sql` | 테이블, 분석 공통 함수, 정답지 스키마 |
| `11_pbl3_generate.sql` | 데이터 생성기 |
| `12_pbl3_views.sql` | 팀 공통 분석 뷰 |
| `13_pbl3_verify.sql` | 무결성 검사(실패 시 에러) + 분포 요약 |

## 규모

| 항목 | 건수 |
|---|---|
| 학생 (2022~2026 입학, 8개 학과, 2개 캠퍼스) | 1,596 |
| 프로그램 시리즈 / 회차 | 35 / 184 (예정 5) |
| 회차 × 대상 학생 | 223,257 |
| 신청 / 출석 | 6,759 / 5,376 |
| 만족도 응답 / 상세 | 3,921 / 20,034 |
| 지출 | 417 |

학생 적극성은 표준정규 분포(평균 0, 표준편차 1)이고, 만족도는 평균 3~4점대 종 모양, 학생별 참여 횟수는 대부분 0~2회이고 일부가 많이 참여하는 긴 꼬리 분포입니다.

## 두 스키마

- **`pbl3`**: 관측 가능한 데이터. 분석과 모델은 여기만 읽습니다.
- **`pbl3_truth`**: 생성기에 심은 정답(학생 적극성, 프로그램 품질, 효과 계수, 출석자의 실제 만족도). **모델 학습에 쓰면 안 되고**, 모델이 추정한 효과를 정답과 비교해 채점할 때만 씁니다. `analytics_reader` 계정은 접근할 수 없습니다.

## 테이블 (public 대응)

| pbl3 | public 대응 | 비고 |
|---|---|---|
| `campus`, `department`, `academic_term`, `program_type`, `survey_question_category`, `budget_item` | 같은 이름 | 코드는 `P3_` 접두어 |
| `student` | `student` | 연락처·누적마일리지 제외. `grade`는 기준일 학년, 과거 학년은 `fn_grade_at` |
| `student_info_change_request` | 같은 이름 | SMS 수신 거부(승인 건)만 |
| `program`, `mileage_criteria` | 같은 이름 | `series_key` 추가(해마다 반복되는 같은 프로그램) |
| `survey`, `survey_question`, `survey_response`, `survey_response_detail` | 같은 이름 | 조사가 **회차 단위** (`survey.session_id` 추가) |
| `expenditure` | `expenditure` | 프로그램 연관 지출만. `session_id` 추가 |
| `program_session`, `program_participant`, `course_timetable`, `academic_event` | 없음 (신규) | 회차·출석·학과·학년별 시간표·시험기간 |

## 분석 공통 함수

같은 기준으로 계산하도록 한 곳에 두었습니다.

- `pbl3.fn_grade_at(입학일, 입학구분, 날짜)`: 그 날짜의 학년 (재학 범위 밖이면 NULL)
- `pbl3.fn_class_conflict(학과, 학년, 날짜, 시작, 종료)`: 그 시간에 전공 수업이 있는가
- `pbl3.fn_near_exam(날짜)`: 시험기간 ±3일
- `pbl3.fn_in_semester(날짜)`: 정규학기 중인가 (아니면 방학)

## 항목별 분석 뷰

| 뷰 | 단위 | 주 사용 |
|---|---|---|
| `mv_candidate` | 회차 × 대상 학생 | **2번** 참여 원인 모델 입력, 4번 |
| `v_session_overview` | 회차 | 2번, 3번. 대상 인원, 수업 충돌률, 신청·출석, 분류별 만족도, 비용 |
| `v_response_scored` | 응답 | **1번**. 분류별 점수, 일괄 응답 여부, 다음 회차 재참여 여부 |
| `v_program_cost` | 프로그램 | **3번**. 출석 1회당·고유 출석자당·만족 출석자당·재참여자당 비용 |
| `v_student_activity` | 학생 | **4번**. 참여 이력, 노쇼, SMS 수신 거부일 |

`mv_candidate`는 그 회차 **이전**에 관측 가능한 정보만 담습니다(직전 회차 출석·응답, 과거 참여 횟수, 당시 SMS 수신 여부 등). 결과 컬럼 `registered`, `attended`는 예정 회차에서 NULL입니다.

## 생성기에 심은 효과 (요약)

정확한 값은 `SELECT * FROM pbl3_truth.coef;`

**참여 (2번)**: 수업 충돌, 시험기간, 방학, 회차가 거듭될수록 피로, 다른 캠퍼스 이동, 금·토요일, 18시 이후, 직전 회차 입소문(평균 내용 만족도), 마일리지 보상, 학년별 프로그램 유형 선호

**만족도 (1번)**: 운영 만족도는 평균이 가장 낮지만 재참여에 **영향이 없습니다**. 재참여는 내용 만족도가 가장 크게 좌우하고, 강사는 중간입니다. 적극성이 낮은 학생 일부는 모든 문항에 같은 점수를 줍니다.

**학생 (4번)**: 신관캠(DAI) 편입생은 적극성이 낮은 숨은 소외 집단입니다. 약 10%는 중간에 이탈하고, 이탈 무렵 SMS 수신 거부가 먼저 나타나며 일부는 자퇴합니다.

**시연용 시나리오** (`pbl3_truth.program_latent.story`)

| 프로그램 | 상황 |
|---|---|
| 코딩테스트 대비 알고리즘 특강 2026 | 내용은 좋은데 4회차부터 수요일 13:00로 옮겨 2~3학년 수업과 겹치며 참여 급감 → "시간 문제" |
| 생성형 AI 활용 특강 2025·2026 | 주제 매력으로 신청은 많지만 품질이 낮고 강사료가 비쌈 → 입소문으로 회차마다 감소, 만족 1명당 비용 최고 |
| MLOps 실무 특강 2026 | 1회차만 진행, 남은 회차(12/8은 기말 직전)는 예측·시간대 추천 대상 |

## 복원 가능성 확인

관측 컬럼만으로 로지스틱 회귀를 돌린 결과입니다 (프로그램·학년 고정효과 포함).

| 효과 | 정답 | 추정 |
|---|---|---|
| 수업 충돌 | −1.40 | −1.30 |
| 시험기간 | −0.90 | −0.80 |
| 회차 피로 (회당) | −0.12 | −0.11 |
| 다른 캠퍼스 | −1.00 | −0.89 |
| 직전 회차 출석 | +2.40 | +3.38 |

주요 효과는 잘 복원됩니다. 직전 회차 출석 효과가 부풀려진 것은 **보이지 않는 적극성이 섞였기 때문**이고, 실제 데이터에서도 생기는 교란이라 1번 분석에서 설명거리가 됩니다. 금요일·저녁 효과는 해당 회차가 적어 약하게 잡힙니다.

## 한계

- 가상 데이터이며 효과 구조는 설계자가 정한 것입니다. 발표에서는 "정답을 아는 데이터로 방법을 검증했다"로 설명합니다.
- 시간표는 학과·학년 단위 대표 시간표입니다. 개인별 수강 내역이 아닙니다.
- 마일리지 신청·TOPCIT는 생성하지 않았습니다.
- 데이터를 다시 만든 뒤 `mv_candidate`만 따로 갱신하려면 `REFRESH MATERIALIZED VIEW pbl3.mv_candidate;`

## 2번 참여 저조 원인 분해·시간대 추천 (`p2/`)

```bash
psql -d swknu_db -f pbl3/reset_pbl3.sql      # 데이터 + 2번용 테이블(15번)
bash pbl3/p2/run_participation.sh            # 모델 학습 → 결과 저장 → 차트 (약 20초)
psql -d swknu_db -f pbl3/p2/demo_p2.sql      # 시연용 조회
```

필요한 파이썬 패키지: pandas, numpy, scikit-learn, matplotlib. DB 드라이버는 필요 없습니다(psql로 입출력). 한글 차트에는 Noto Sans CJK KR 또는 나눔고딕 글꼴이 필요합니다.

| 파일·객체 | 내용 |
|---|---|
| `15_pbl3_participation.sql` | 결과 테이블 4개, 후보 시간대 뷰 `mv_p2_whatif`, 추천 뷰 `v_p2_recommendation` |
| `p2/participation_model.py` | 신청·출석 로지스틱 회귀, 시간 분리 검증, 요인 분해, 시간대 시뮬레이션 |
| `p2/make_charts.py` | `p2/charts/*.png` 발표용 차트 |
| `pbl3.p2_effect` | 요인별 효과(계수·승산비) |
| `pbl3.p2_session_factor` | 회차별 "이 요인만 없었다면 늘었을 신청 인원" |
| `pbl3.p2_slot_forecast` | 같은 주 평일 5일 × 5개 시각별 예상 신청·출석 |
| `pbl3_truth.v_p2_recovery` | 모델 추정 계수 vs 생성기 정답 (채점용) |

모델 결과 요약: 학생 단위 AUC 0.87, 회차별 신청 인원 오차 13명(평균 신청률만 쓰면 22명). 수업 충돌·캠퍼스 이동·시험기간·직전 회차 평가 효과는 정답에 가깝게 복원. 방학 효과는 방학 프로그램이 모두 캠프·해커톤이라 프로그램 효과와 분리되지 않음(수집 설계 개선 과제).
