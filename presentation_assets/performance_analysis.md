## 2. A — 만족도 기반 90일 재참여 예측

### 비교 기술·목적

다수 클래스 예측, 전체 유효 응답으로 학습한 Logistic Regression, 의심 응답을 학습에서만 제외한 동일 Logistic Regression을 비교했다. 응답 품질을 고려한 학습이 예측력을 개선하는지 확인하는 실험이다. 의심 응답이 실제 불성실 응답이라는 정답을 가정하지 않는다.

입력은 CONTENT·FACILITY·INSTRUCTOR·OPERATION·SCHEDULE의 실제 분류별 평균 점수 5개다. `StandardScaler`와 `LogisticRegression(max_iter=1000, random_state=42)`를 사용했다. 전처리도 학습 데이터에서만 적합했다. 생성기 정답·잠재 변수는 학습 입력에 사용하지 않았다.

양성은 **설문 제출 후 90일 이내 후속 회차 출석**이며 같은 프로그램의 다음 회차도 포함한다. 미관찰·기회 없음은 음성으로 간주하지 않았다.

### 데이터 분리·재현

- 원본 코드의 제출 시각 65% 분위수를 분리 시점으로 유지했다.
- SHA-256 학생 식별자 해시를 5로 나눈 나머지가 0인 학생을 평가 후보로 유지했다.
- 학습: 평가 학생 제외 + 제출 후 90일 라벨이 분리 시점 전에 확정된 1,179건, 학생 418명.
- 의심 제외 학습: 같은 학습 표본에서 86건 제외, 1,093건. 평가 표본은 바꾸지 않았다.
- 평가: 분리 시점 이후 동일한 **194건, 학생 85명**, 양성 141건·음성 53건. 학습/평가 학생 중복 0명.
- 원본 분리 시점은 `2026-03-24 18:54:11.725778176+09:00`, 마지막 학습 라벨 확정은 2026-03-07 16:54:58.099140+09, 첫 평가 설문은 2026-03-24 19:02:26.811628+09이다.
- CSV 재입력의 datetime 정밀도로 분리 시점이 마이크로초 단위로 표현되지만 학습/평가 행 선택과 모든 지표는 일치한다.

원본 `analysis/model.py`의 `evaluate` 함수를 분석용 스냅샷에서 그대로 추출해 실행했다. 지표·건수 21개 비교는 [satisfaction_reproduction_check.csv](data/satisfaction_reproduction_check.csv), 평가 확률·예측은 [satisfaction_test_predictions.csv](data/satisfaction_test_predictions.csv), 분리 목록은 [satisfaction_split.csv](data/satisfaction_split.csv)에 있다. 상세 설정과 한계는 [experiment_protocol.json](data/experiment_protocol.json)에 기록했다.

### A-1 / A-2 결과

| 모델 | 학습 n | 평가 n | Accuracy | Precision | Recall | F1-score | ROC-AUC |
|---|---:|---:|---:|---:|---:|---:|---:|
| 다수 클래스 기준 | 1,179 | 194 | 0.7268 | 0.7268 | 1.0000 | 0.8418 | 0.5000 |
| Logistic Regression | 1,179 | 194 | 0.7320 | 0.7306 | 1.0000 | 0.8443 | 0.6813 |
| 의심 응답 제외 Logistic | 1,093 | 194 | 0.7423 | 0.7407 | 0.9929 | 0.8485 | 0.6867 |

Accuracy는 전체 정답률, Precision은 재참여로 예측한 응답 중 실제 재참여 비율, Recall은 실제 재참여 중 탐지 비율, F1은 Precision과 Recall의 조화평균이다. ROC-AUC는 임계값을 변화시킨 순위 판별력을 나타낸다. Accuracy 등은 모델 기본 결정 기준인 확률 0.5를 사용했다.

일반 Logistic은 기준 대비 AUC +0.1813, Accuracy +0.5155%p다. 의심 제외 학습은 일반 Logistic 대비 **AUC +0.0053526, Accuracy +1.0309%p**, 기준 대비 Accuracy +1.5464%p다. 평가 정답은 기준 141건 → 일반 142건 → 의심 제외 144건이다.

혼동행렬을 `[TN, FP; FN, TP]`로 쓰면 일반 모델은 `[1,52;0,141]`, 의심 제외 모델은 `[4,49;1,140]`이다. 품질 보정에서 오탐 3건이 줄고 실제 재참여자 1건을 추가로 놓쳤다. 다수 클래스 모델은 전원을 재참여로 예측하므로 Recall과 F1이 높아도 음성을 판별하지 못한다. 한 지표만으로 우열을 결론 내리면 안 된다.

### A-3 추가 실험과 의미

같은 데이터에 결정적인 Logistic을 단순 반복 적합해 가짜 오차막대를 만들지 않았다. **학생 단위 paired bootstrap**을 두 방식으로 수행했다. 동일 학생의 여러 응답을 함께 복원추출하고, 각 반복에서 두 모델에 같은 학생 추출 결과를 적용했다. 난수 시드는 20261124다.

| 추가 실험 | 방법 | 결과 |
|---|---|---|
| 학습 변동성 1,000회 | 학습 학생 418명을 복원추출 → 일반 적합 / 같은 표본에서 의심 응답 제외 후 적합 → 고정 194건 평가 | 일반 AUC **0.6620 ± 0.0326 SD**, 제외 **0.6707 ± 0.0257 SD** |
| 학습 재표집의 paired 차이 | 위 1,000개 ΔAUC의 분포 | 평균 +0.0087, 2.5–97.5% 구간 **[−0.0103, +0.0343]** |
| 평가 불확실성 2,000회 | 원래 학습한 두 모델 고정 → 평가 학생 85명 복원추출 → 같은 응답들에서 두 AUC 계산 | 관측 ΔAUC +0.0054, 95% percentile CI **[−0.0038, +0.0156]** |

학습 재표집 구간은 고정 평가 집합에서의 **학습 변동성 분포**이며 모집단 일반화 성능의 신뢰구간으로 부르지 않는다. 평가 CI는 고정된 학습 모델과 관측 학생 분포에 조건부인 근사 구간이다. 둘을 합친 이중 재표집 신뢰구간은 계산하지 않았다. 기준 모델의 AUC는 항상 0.5이므로 A-3는 품질 보정 비교에 집중했다.

**평가 차이 CI가 0을 포함하므로 개선이 충분히 확실하다고 결론 내릴 근거가 없다.** 모든 반복값은 [satisfaction_bootstrap_replicates.csv](data/satisfaction_bootstrap_replicates.csv), 수치 요약은 [satisfaction_bootstrap_summary.json](data/satisfaction_bootstrap_summary.json)에 있다. JSON 원본에 없던 CI는 이 추가 실험에서 계산한 것으로 명확히 구분했다.

한계: 단일 합성 세계·단일 시점 holdout, 학생 85명의 작은 평가 집합, 공통 프로그램/회차에 따른 상관을 추가로 재표집하지 않은 점, 생성기의 적극성 같은 잠재 공통 요인이 예측 연관성에 반영되는 점이 있다. 원본 프로토콜의 시간 분위수 선택도 완전히 사전에 지정된 외부 평가 설계는 아니다. 운영 점수의 양의 계수는 운영 개선의 인과효과가 아니다.

PPT 설명: “기준 AUC 0.5000에서 만족도 기반 모델은 약 0.68을 기록했습니다. 의심 응답 제외 학습은 0.6867로 소폭 높았지만 차이의 신뢰구간에 0이 포함되어 개선을 단정하지 않았습니다.”

## 3. B — 시간표 기반 참여 저조 분석

### 확인 결과와 실험 목적

비교하고 싶은 기술은 기준 / 기본 특징 / 시간표 추가 / 전체 특징 모델이다. 목적은 **같은 예측 대상과 같은 평가 표본**에서 시간표·수업 충돌 정보의 추가 가치를 검증하는 것이다. 하지만 조사한 브랜치에서 발견한 것은 `pbl3.mv_candidate`, `v_session_overview`, 생성기와 정답 계수이고, 이를 학습하는 참여 예측 모델·평가 분할·예측 확률·결과 파일은 없었다.

**B-1/B-2/B-3: 구현 또는 결과 파일 확인 필요. PPT의 AUC 0.69는 참여 분석 결과로 재현할 근거가 없다.** A의 0.6867을 반올림하면 0.69가 되지만, 예측 대상·평가 표본이 다르므로 B의 성능으로 사용할 수 없다. 개선량·유의성도 평가하지 못했다.

`mv_candidate`에는 학과/학년, 프로그램 유형, 요일/시각, 수업 충돌 여부, 시험기간, 캠퍼스 이동, 과거 신청/출석/노쇼, 직전 회차 점수 및 `registered`, `attended` 결과가 있다. 출석자 설문만 모인 A 데이터와 대상학생 전체를 포함하는 B 데이터는 다르다.

### 추가 구현 시 지켜야 할 평가 계약

| 항목 | 필요한 작업 |
|---|---|
| 예측 대상 | 먼저 학생×회차의 `registered` 또는 `attended` 중 하나를 고정. 두 목표의 AUC를 혼합하지 않음 |
| 공통 데이터 | 완료 회차만 사용, 모든 특징 집합에서 같은 학습/평가 행 유지, 예정 회차는 정답 평가에서 제외 |
| 시간 분리 | 회차 날짜 기준으로 앞 시점 학습/뒤 시점 평가, 같은 회차를 행 단위 무작위로 나누지 않음, 최종 평가 전 시점에서 튜닝 |
| 기준 모델 | 학습 데이터의 다수 클래스 또는 명시한 단순 모델 |
| 기본 특징 | 학년·학과·프로그램 유형·마일리지 등. 시간표·요일·시각·충돌 정보 제외 |
| 시간표 추가 | 같은 기본 특징에 수업 충돌 및 요일·시각 추가. 학생 단위 `class_conflict`와 회차 평균 `conflict_rate`의 단위를 구별 |
| 전체 특징 | 예측 시점에 알려진 시험기간·캠퍼스 이동·과거 이력 등을 추가. 실제 파일이 생기면 구현에 맞게 목록 확정 |
| 전처리 | 결측 대치·표준화·인코딩은 학습 데이터에서만 적합 |
| 정답지 | `pbl3_truth`는 학습·튜닝·특징 선택 입력에서 제외; 최종 추정 후 채점에만 사용 |

**미래 정보 누수 점검이 추가로 필요하다.** 기존 candidate 뷰의 `own_content`/`prev_avg`는 직전 회차 설문을 읽을 때 `responded_at < 예측 회차 시작시각` 조건을 두지 않는다. 생성기는 회차 종료 후 최대 약 96시간까지 설문 제출 시각을 만들고, 캠프는 매일 열리므로 ‘직전 회차 점수’라도 현재 회차 예측 시점에는 아직 제출되지 않았을 수 있다. 따라서 뷰의 “회차 이전 정보” 주석만으로 시간 안전성을 보장할 수 없다. 향후 분석용 SELECT에서 제출 시각을 제한하고 과거 집계를 다시 계산해야 한다. 이번에는 기존 뷰를 변경하지 않았다.

B-2는 `attended`를 예측한 전체 대상학생 확률이 생기면 회차별 `ΣP(attended)`를 실제 출석 인원과 비교할 수 있다. 이는 개인 이진 확률의 합에 따른 **기대 인원 추정**이며 전용 인원 회귀 모델이 아니다. `registered` 확률의 합은 예상 신청 인원이며 출석 인원과 비교하면 안 된다. A의 재참여 확률도 회차 출석 확률이 아니므로 대신 합산하지 않았다. MAE/RMSE와 확률 보정 여부를 별도로 평가해야 한다.

B-3용 생성기 정답은 [participation_truth_reference_only.csv](data/participation_truth_reference_only.csv)에 독립 보존했다. 신청 logit의 수업 충돌 −1.40, 시험기간 −0.90, 캠퍼스 이동 −1.00, 직전 회차 평균 내용 점수 1점당 +0.80, 회차 1증가당 피로 −0.12다. 출석 단계에는 다른 계수가 있다. **추정 모델이 없으므로 직접 비교하지 않았다.**

추후에도 같은 목표·로짓 링크·원시 변수 스케일을 확인해야 한다. 표준화 계수는 원시 단위로 환산해야 하며, 생성기 직전 점수는 잠재 실제 점수이고 뷰는 관측 설문 점수라는 차이도 있다. 적극성·매력 같은 누락 요인, 신청 정원 제한, 신청/취소/출석의 여러 단계 때문에 관측 모델 계수가 생성기 계수와 같아야 한다고 가정할 수 없다. A의 표준화 만족도 계수와 B의 신청 생성 계수는 직접 비교 대상이 아니다.

PPT 설명: “시간표 기반 참여 분석을 위한 데이터 구조는 있지만, 동일 평가 집합의 모델 비교 결과가 저장소에서 확인되지 않아 AUC와 개선량을 제시하지 않았습니다. 다음 실험에서 시간표를 추가한 효과를 검증할 예정입니다.”

## 4. C — 예산 효율 분석 방법 비교

### 비교 기술·목적·지표

단순 지출/출석 단가와 만족도·반복 출석까지 결합한 집계 방법을 비교한다. 교육 프로그램 평가 관점과 순위가 실제로 달라지는지 확인하는 실험이며 머신러닝 정확도 실험은 아니다. ROC-AUC·정확도·예측 성능 향상률은 계산하지 않았다.

사용한 정의는 최신 main의 [`v_program_cost`](data/sources/pbl3/12_pbl3_views.sql) 그대로다.

| 지표 | 분자 / 분모 |
|---|---|
| 승인 지출 총액 | `status='APPROVED'` 지출 합계 |
| 고유 출석자당 비용 | 승인 지출 / 같은 프로그램에 한 번 이상 출석한 고유 학생 수 |
| 만족 출석자당 비용 | 승인 지출 / 동일 점수 반복을 제외한 완료 응답의 학생·프로그램별 **내용 점수 평균 ≥ 4**인 출석 학생 수 |
| 반복 출석자당 비용 | 승인 지출 / 같은 프로그램에 **2회 이상** 출석한 고유 학생 수 |

학생별로 먼저 집계하므로 여러 회차에 출석하거나 설문을 여러 번 제출해도 분모에서 같은 학생을 중복 집계하지 않는다. 설문 없는 출석자는 만족 여부를 확인할 수 없어 만족 분모에 들어가지 않는다. 따라서 만족 단가는 만족도뿐 아니라 **설문 응답률·선택 편향·출석 반복·제외 규칙**에도 영향을 받는다. 프로그램 규모·기간·진행 방식이 같다는 뜻도 아니다.

### 승인·중복·NULL 검증

- 승인 402건 **157,557,000원**을 비용에 포함했다. 반려 15건 **8,849,000원**은 포함하지 않았다. 반려 후 재신청 승인은 별도 승인 기록만 포함된다.
- 별도 `APPROVED` 합계와 모든 프로그램의 뷰 비용을 대조해 불일치 0건이다.
- 별도 `COUNT(DISTINCT student_no)`와 뷰의 고유 출석 인원을 대조해 불일치 0건이다. 학생×회차 중복 키도 0건이다.
- 0인 분모는 `NULLIF(...,0)`으로 NULL 처리된다. 이번 데이터에는 만족 출석자 0명인 프로그램이 없어 해당 조건의 실사례 검증은 불가능하다. SQL 정의를 확인했으며, 0명 조건에서 잘못된 비NULL이 있는지 확인한 위반 건수는 0건이다. 반복 출석자 0명인 MLOps 사례의 단가는 실제 NULL이다.
- NULL을 0원 또는 최고 효율로 변환하지 않는다. 비용은 원본 뷰처럼 원 단위 반올림했다.
- 상세 SQL 검증은 [budget_validation.csv](data/budget_validation.csv), 지출 상태별 집계는 [budget_expenditure_status.csv](data/budget_expenditure_status.csv)에 있다.

전체 프로그램의 [유형 내 순위 CSV](data/budget_rankings_all_programs.csv)는 참고용이다. 연도·기간·운영 방식·미완료 회차 차이가 있으므로 예산 배분의 최종 판단으로 해석하지 않는다.

### C-3 품질 기준 통일 민감도

현재 예산 뷰는 동일 점수 반복을 전부 제외한다. Survey Insight 기본 정책은 문항당 2초 미만 또는 상대적으로 빠른 응답에 감점하며, `max(0,100−빠름×40−반복×15−동시×20)<70`일 때 의심으로 제외한다. 상대 기준은 시간 표본 10건 이상, 하위 10% 이하이면서 중앙 시간의 25% 미만이다.

따라서 느린 동일 점수 응답(85점)은 Survey Insight에서 유지되지만 예산에서는 제외된다. 반대로 빠르면서 점수가 서로 다른 응답은 Survey Insight에서 제외될 수 있지만 예산에서는 유지된다. 어느 쪽도 실제 불성실함의 정답 라벨은 아니다.

내용 평균 ≥4와 승인 지출은 고정하고, 응답 제외 규칙만 Survey Insight와 일치시킨 **별도 SELECT**를 실행했다. 원래 DB 뷰와 기준은 변경하지 않았다.

| 2025년 특강 | 기존 만족 인원→통일 후 | 기존 만족 단가→통일 후(원/명) | 단가 변화 |
|---|---|---|---:|
| 파이썬 기초 | 33→37 | 101,024→90,103 | −10.81% |
| AI 리터러시 | 9→9 | 291,344→291,344 | 0.00% |
| 데이터 분석 | 98→97 | 41,519→41,947 | +1.03% |
| 클라우드 입문 | 39→39 | 89,451→89,451 | 0.00% |
| 생성형 AI 활용 | 21→20 | 266,305→279,620 | +5.00% |

전체 35개 중 24개에서 만족 분모가 달라졌고 만족 단가 변화 범위는 **−17.95%~+10.00%**다. 이는 품질 보정의 성능 향상이 아니라 지표 정의에 대한 민감도다. 대상 5개의 비용 순위는 규칙 통일 후에도 유지됐다. 응답을 제외하면 개인별 평균이 다시 계산되므로 만족 인원이 항상 증가하거나 감소하는 것도 아니다.

[budget_quality_sensitivity.csv](data/budget_quality_sensitivity.csv)는 모든 프로그램에 대해 기존 제외/Survey Insight 제외/완료 전체 3개 정책, CONTENT 기준/이전 5문항 기준을 함께 기록한다. [budget_quality_policy_comparison.csv](data/budget_quality_policy_comparison.csv)는 정책 차이를 계산한 표다. 이전 정의와 최신 정의를 같은 비용 열에 섞지 않았다.

## 5. 재실행·검증

전달된 CSV/JSON으로 그림을 재생성하는 데 DB는 필요 없다.

```powershell
python -m pip install -r presentation_assets/scripts/requirements.txt
python presentation_assets/scripts/generate_performance_charts.py
python presentation_assets/scripts/validate_assets.py
```

기본값은 학습 1,000회·평가 2,000회·seed 20261124다. 캐시는 입력/설정/라이브러리 버전을 확인한 경우에만 재사용한다. 다른 반복 횟수는 `--bootstrap-train`, `--bootstrap-test`, `--seed`로 지정할 수 있다. 원본 A-1/A-2는 저장 JSON 값, A-3는 추가 실험값이다.

독립 DB부터 재현하려면 PostgreSQL 16 바이너리와 psycopg가 필요하다. 해당 스크립트는 사용자 접속 URL을 받지 않고 매번 `.local/pbl3_performance_*`에 새 클러스터·새 DB를 만든다. 빈 DB 여부를 검사한 뒤에만 스키마를 적용하며 끝나면 서버를 종료한다. 비밀번호는 출력하거나 결과물에 저장하지 않는다. 기존 DB를 지정해 실행할 수 없다.

```powershell
python presentation_assets/scripts/prepare_experiment_data.py --pg-bin 'C:\Program Files\PostgreSQL\16\bin'
python presentation_assets/scripts/generate_performance_charts.py
python presentation_assets/scripts/validate_assets.py
```

이 환경의 psycopg는 이미 설치된 `.local/python`에 있어 데이터 추출 시에만 해당 폴더를 `PYTHONPATH`에 지정했다. 그래프 생성에는 시스템에 설치된 numpy/pandas/matplotlib/scikit-learn을 사용했다. 검증 환경은 Python 3.14.6 / PostgreSQL 16.15 / numpy 2.4.6 / pandas 3.0.3 / matplotlib 3.11.0 / scikit-learn 1.9.0 / Malgun Gothic이다.

원본 스냅샷 재캡처가 필요할 때만 `capture_repository_sources.py`를 실행한다. 전달된 manifest의 커밋을 사용하면 정확한 소스를 지정할 수 있다. 움직인 브랜치를 새로 캡처하면 데이터와 수치가 달라질 수 있으므로 전달된 스냅샷을 보존하는 편이 좋다. 이 도구도 checkout/merge/fetch 또는 기존 DB 변경을 하지 않는다.

[validation_report.json](data/validation_report.json)은 소스 해시, 예측값으로 재계산한 지표, 라벨 시간 분리, 재표집 요약, 비용식/정책 일치, 해상도·화면비·SVG 존재를 검사한 결과다. 이는 기존 업무 DB 전체 회귀 테스트를 실행했다는 뜻은 아니다. PNG를 열어 한글, 수치, 범례와 순위 연결선도 확인했다.
