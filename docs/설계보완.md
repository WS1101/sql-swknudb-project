# 1차 설계 대비 변경 사항 및 구현 정책

기준 ERD: `docs/erd_v2.dbml` (public 테이블 32개. 분석 뷰는 ERD에 그리지 않음)

변경은 세 종류로 나눈다.

| 종류 | 의미 |
|---|---|
| 구현 | PostgreSQL로 옮기면서 필요해진 변경 |
| 보완 | 1차 설계의 누락·오류·불일치 수정 |
| 확장 | 요구사항 밖 추가 |

---

## 1. 전체 공통 규칙

| 항목 | 1차 | 구현 | 종류 | 이유 |
|---|---|---|---|---|
| 테이블·컬럼명 | 대문자 (USER, STUDENT) | 소문자 snake_case (app_user, student) | 구현 | PostgreSQL은 따옴표 없는 이름을 소문자로 처리 |
| 일시 | datetime | timestamptz | 구현 | PostgreSQL에 datetime 없음 |
| 작은 정수 | tinyint | smallint | 구현 | PostgreSQL에 tinyint 없음 |
| 여부값 | char(1) 'Y'/'N' | boolean | 구현 | |
| 학번·교번 | varchar(15) | varchar(20) | 구현 | app_user.user_id와 FK 타입 일치 |
| 금액 | decimal(15,0) | bigint (원 단위) | 구현 | |
| 대리키 | increment | GENERATED ALWAYS AS IDENTITY | 구현 | |
| 변경로그 값 | text | jsonb | 구현 | JSON 형식 검증, 내부 조회 가능 |
| FK 인덱스 | 없음 | FK 컬럼마다 인덱스 직접 생성 | 구현 | PostgreSQL은 FK 인덱스를 자동 생성하지 않음 |
| 코드 마스터 삭제 | 논리삭제 | is_active = false, DELETE 없음 | 유지 | 과거 참조 보존 |

## 2. 사용자·권한 (01_common)

| 변경 | 1차 | 구현 | 종류 | 관련 |
|---|---|---|---|---|
| 사용자 테이블명 | USER | app_user | 구현 | 예약어 |
| user_id 표기 | 5.2·6.2는 'S+학번' / 7.1은 접두사 없음 | 접두사 없이 학번·교번 | 보완 | 보고서 내 불일치. 7.1 기준 |
| 성명 | ADMIN.name에만 존재 | app_user.user_name | 보완 | FR-3-01, 학생 성명 누락 |
| 비밀번호 | password | password_hash (bcrypt) | 구현 | 평문 저장 금지 |
| 학생/관리자 배타성 | 비즈니스 규칙 | student·admin에 user_type + (id, user_type) 복합 FK | 보완 | DB가 강제 |
| 권한 코드 | permission_name만 | permission_code 추가 | 보완 | FR-8-03 |
| 권한 부여 기록 | 없음 | user_role.granted_by, granted_at | 보완 | DR-8-01 |
| 로그 보호 | 명시만 | 트리거로 UPDATE·DELETE 차단 | 보완 | 보고서 5.2 |

### 역할과 권한

| 역할 | 권한 |
|---|---|
| STUDENT | STUDENT_READ_SELF, STUDENT_CHANGE_REQUEST, TOPCIT_READ_SELF, MILEAGE_READ_SELF, MILEAGE_APPLY, SURVEY_RESPOND |
| GENERAL_ADMIN | STUDENT_READ_ALL, STUDENT_CHANGE_PROCESS, TOPCIT_READ_ALL, MILEAGE_READ_ALL, BUDGET_READ, SURVEY_READ, CHANGE_LOG_READ |
| MASTER_ADMIN | 위 전부 + TOPCIT_MANAGE, MILEAGE_MANAGE, PROGRAM_MANAGE, BUDGET_MANAGE, EXPENDITURE_MANAGE, SURVEY_MANAGE, ROLE_MANAGE |

일반관리자는 조회와 학생정보 변경 처리만 가능하고, 마일리지·예산·지출 승인은 마스터관리자만 가능하다. 승인 함수가 `fn_assert_permission`으로 실제로 확인한다.

## 3. 기준정보 (02_master)

| 변경 | 1차 | 구현 | 종류 | 관련 |
|---|---|---|---|---|
| 학과 계열 | track_type char(2), 값 ENG/NAT | char(3) + CHECK, 값 ENG/DAI | 보완 | 3글자 값이 char(2)에 들어가지 않음. 학과 구성 변경에 맞춰 계열 코드 조정 |
| 교수 PK | int | varchar(20) 교번 형식 | 보완 | 보고서 2.3 "USER 서브타입 전환이 쉬운 PK" |
| 교수 위치 | 학생 영역 | 기준정보 영역 | 구현 | 예산이 참조 |
| 지출주체 코드 | varchar(5) | varchar(20) | 구현 | 코드값 길이 |
| 학기 (신규) | 없음 | academic_term | 확장·보완 | 기간별 조회, 학기별 분석 |
| 프로그램유형 (신규) | program_category 자유 입력 | program_type 코드 테이블 | 보완 | DR-8-02 |
| 문항분류 (신규) | 없음 | survey_question_category | 확장 | 조사 간 문항 비교 |

**학기 사용 방식**: 1차의 "학기는 날짜로 계산" 결정을 유지한다. 다른 테이블에 term_id를 두지 않고, 날짜가 academic_term 기간에 속하는지로 판별한다. 학기 코드는 1, S(여름), 2, W(겨울)이며 1년을 빈틈없이 정의한다. 기간 겹침은 `EXCLUDE USING gist (daterange(start_date, end_date, '[]') WITH &&)`로 DB가 거부한다.

## 5. TOPCIT (04_topcit)

| 변경 | 1차 | 구현 | 종류 | 관련 |
|---|---|---|---|---|
| 응시 시점 학년·학과 | 없음 | grade_at_exam, dept_code_at_exam | 보완 | FR-4-04, Q04 |
| 스냅샷 입력 | — | 04 파일의 BEFORE INSERT 트리거가 student 현재 값으로 채움 (직접 넣으면 유지) | 구현 | |
| 점수 저장 타입 | int | int (0~1000 CHECK) | 유지 | TOPCIT는 정수 점수 체계. 소수 입력 시 반올림되므로 외부 연계 시 입력 단계에서 검증 |
| 회차명 | UNIQUE | UNIQUE | 유지 | 초기 구현 누락 후 보완 |
| 마일리지 기준 구간 | min 포함, max 미포함, max NOT NULL | `[min, max)`, **max NULL = 상한 없음** | 보완 | 500점 이상 구간 표현. 1000점이 빠지지 않음 |

**점수 범위**: TOPCIT 총점 1,000점 기준 0~1000.

## 9. 업무 함수 (08_procedures)

| 구역 | 함수 | 하는 일 |
|---|---|---|
| 공통 | fn_write_change_log | 변경 로그 기록. 테이블명 오타 거부 |
| 공통 | fn_assert_admin | 활성 관리자 확인 |
| 공통 | fn_assert_permission | 역할 권한 확인 (user_role → role_permission → permission) |
| 학생정보 | fn_create_student_info_change_request | 변경 요청 (기존 값 자동) |
| 학생정보 | fn_approve_student_info_change | 승인 → 학생 정보 반영 |
| 학생정보 | fn_reject_student_info_change | 반려 (사유 필수) |
| 마일리지 | fn_create_mileage_application | 신청 (기준표 계산), 직권등록 시 즉시 승인 |
| 마일리지 | fn_approve_mileage_application | 승인 → 누적 + |
| 마일리지 | fn_reject_mileage_application | 반려 (사유 필수) |
| 마일리지 | fn_cancel_mileage_application | 취소 (대기만) |
| 마일리지 | fn_revoke_mileage_application | 회수 → 누적 − |
| 예산 | fn_confirm_initial_budget | 최초예산 확정 |
| 지출 | fn_create_expenditure | 지출 등록 |
| 지출 | fn_approve_expenditure | 승인 (한도·기간·확정 검사, 90% 경고) |
| 지출 | fn_reject_expenditure | 반려 (사유 필수) |

모든 승인 함수는 같은 순서를 따른다: 관리자·권한 확인 → 대상 행 `FOR UPDATE` → 상태 확인(이중 처리 방지) → 업무 규칙 → 변경 → 로그. 함수 안에서 에러가 나면 그 함수의 모든 변경이 롤백된다.

**변경 로그 형식**

| action_type | before_value | after_value |
|---|---|---|
| CREATE | NULL | 생성된 행 전체 |
| 그 외 | 바뀐 항목의 이전 값만 | 바뀐 항목의 새 값만 |

예외: 회수 로그는 원래 승인자·승인일시와 회수 금액을 함께 남긴다.

## 10. 분석 영역 (09_analytics) — 요구사항 밖 확장

**왜 추가했나**: 1차 설계는 업무 처리 중심이었다. 쌓인 만족도·마일리지·TOPCIT 데이터를 프로그램 개선과 예산 판단에 쓰려면, 운영 데이터를 건드리지 않고 개인정보 없이 분석할 공간이 필요하다.

| 구성 | 내용 |
|---|---|
| analytics 스키마 | 업무 테이블(public)과 분리 |
| v_survey_response_final | 학생·조사별 최신 완료 응답 (Q10·Q11 집계 기준을 고정) |
| v_satisfaction_summary | 학기·프로그램유형·문항분류·학과·학년별 만족도. 평균과 함께 합계·개수 제공 |
| v_student_features | 학생별 학과·학년·마일리지(승인 내역 재계산)·TOPCIT·만족도. 이름·연락처 없음 |
| analytics_reader | 분석 전용 계정. analytics 뷰만 SELECT |

**뷰로 둔 이유**

| 이점 | 설명 |
|---|---|
| 항상 최신 | 저장하지 않고 조회 시 원본에서 계산 |
| 기준 통일 | "승인된 것만", "최신 완료 응답만" 규칙을 한 곳에 정의 → 누가 조회해도 같은 숫자 |
| 실수 방지 | 영역별로 먼저 합산한 뒤 결합 → 조인으로 합계가 부풀지 않음 |
| 보안 | 뷰는 소유자 권한으로 원본을 읽으므로, 뷰 권한만 주면 뷰의 컬럼만 노출 |
| 재사용 | 차트·대시보드·모델이 같은 뷰를 입력으로 사용 |

**권한**: reset이 public 스키마를 다시 만들면서 기본 사용 권한이 없어, 분석 계정은 public 스키마 단계에서 차단된다(업무 테이블 42501, 업무 함수 42883). T13·D4에서 확인.

**활용 예시**: 뷰를 CSV로 내보내 `analysis/plot_analytics.py`로 학년별 마일리지·TOPCIT, 학과별 마일리지, 프로그램 유형별 만족도를 시각화했다.

**한계**: 조회 시마다 계산하므로 데이터가 커지면 구체화된 뷰(materialized view)로 전환한다. 프로그램 참여는 마일리지 승인·설문 응답으로만 추정 가능하다.

## 12. 미구현·한계

| 항목 | 내용 |
|---|---|
| 연락처 암호화 | 가상 데이터 사용으로 미구현 |
| 학생 본인 데이터 접근 통제 | DB 권한·뷰로 차단하지 않음. 역할·권한 데이터와 조회 범위 검증 SQL로 대체 |
| 지출 취소 | 상태값은 있으나 함수 없음 |
| 교수 로그인 | 교수는 독립 기준정보 |
| 프로그램 참여자 | 테이블 없음. 만족도 응답 자격을 FK로 검증하지 않음 |
| 함수 우회 | 업무 테이블 직접 UPDATE 시 함수 규칙 미적용 |
| 예측 모델 | 결과 테이블(model_run 등)은 데이터 규모·학기 범위 한계로 제외 |
