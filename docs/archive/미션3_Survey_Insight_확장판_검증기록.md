## DB 확장과 공통 테이블 영향

`05_survey_insight.sql`이 `schema/10_survey_insight.sql`만 실행한다. 기존 `01_schema.sql`, `02_seed.sql`, `03_queries.sql`, `04_tests.sql`, `reset.sql`의 실행 순서를 바꾸지 않는다. 새 SQL은 트랜잭션으로 적용되며 재적용할 수 있다. 기존 스키마를 먼저 설치해야 한다.

| 새 테이블 | 위치 | 목적·무결성 |
|---|---|---|
| survey_response_observation | analytics | 응답 FK/PK, started_at, 합성 생성 유형. 미측정 과거 시각은 NULL/행 없음 |
| survey_insight_setting | analytics | 기본 임계값·감점. 단일 설정 행과 범위 CHECK. 화면 변경은 인자만 전달하며 저장하지 않음 |
| survey_demo_program | analytics | 합성 프로그램 FK/PK와 생성 버전. 기존/신규 합성 분석을 분리 |
| participation_coverage | analytics | 데이터 출처별 출석·기회 수집 시작/종료와 근거. 기존 데이터에는 자동 생성하지 않음 |
| program_attendance | public | 팀 공용 실제 출석. 학생·프로그램 FK, UNIQUE, 출석 시각·증거·데이터 출처 |
| program_opportunity | public | 팀 공용 학생별 실제 후속 기회. 학생·프로그램 PK/FK, 제공/예정 시각과 선후 CHECK |

공통 테이블 **컬럼 변경은 없다**. 제출 시각 UPDATE와 시작 시각 INSERT/UPDATE 양쪽에 확장 트리거를 추가하여 started_at ≤ responded_at을 강제한다. 시작 입력 시 응답 행을 잠가 동시 갱신의 시간 역전을 막는다. 일반 업무 계정이 analytics 원본을 읽을 권한 없이도 시간 검증을 거치도록 해당 검증 함수는 고정 search_path의 SECURITY DEFINER로 실행한다. 기존 완료·답변 보호 트리거는 유지한다.

`program_attendance`는 마일리지·신청에서 자동 채우지 않는다. 향후 팀원의 참여 분석도 이 공통 테이블에 출석 근거를 기록할 수 있다. 다회차 출석은 현재 한 학생·프로그램 1건이라는 제한이 있으며 세션 테이블 확장은 후속 과제다.

| 새 뷰/함수 | 집계 단위·역할 |
|---|---|
| v_survey_insight_program | 프로그램 1행, 출처와 실제 출석 기록 수 |
| v_survey_insight_base | 응답 1행, 점수 합/개수·분산·기대 문항 수·시간·최신 여부. 내부용 |
| v_survey_insight_category | 응답·문항분류별 점수 합/개수 |
| fn_survey_quality(config,source) | 응답별 절대/상대 속도·동일 점수·품질 점수·상태·사유 |
| fn_survey_summary(config,source) | 프로그램별 출석 수, 유효·의심·정보 부족 수, 원본/제외/가중 평균 |
| fn_survey_followup(asof,source) | 응답별 90일 관찰 상태·후속 기회 수·실제 재참여 |

품질·집계·후속 함수는 고정 search_path의 SECURITY DEFINER이며 PUBLIC 실행 권한을 회수하고 기존 `analytics_reader`에만 조회/실행을 부여한다. 설정/시간 원본/출석 원본과 내부 base 뷰는 reader에 공개하지 않는다. 이름·연락처는 앱에 로드하지 않으며, 학번은 내부 JOIN 후 화면에서 세션별 HMAC 가명으로만 표시한다. 응답 상세는 CSV로 내보내지 않는다. 5건 미만 학과·학년 집단은 제외율 표에서 숨긴다. 현재는 로컬 관리자 프로토타입이며 웹 로그인·RLS는 미구현이다.

## 분석 알고리즘과 정확한 의미

실제 수식과 설정 범위는 [실행 안내](../../analysis/README.md)에 명시했다. 기본 지표는 100에서 빠름 40, 반복 15, 동시 발생 20을 감점하며 70 미만만 의심 응답으로 제외한다. 느린 반복은 85, 빠른 반복은 25, 빠른 비반복은 60이다. 관측 정보가 부족하면 지표는 NULL이다. 이는 확률이 아니며 실제 불성실 정답 레이블에 대한 정확도를 측정하지 않았다.

시간 통계는 **같은 조사의 최신 완료 유효 응답 중 시간이 측정된 건**만 사용한다. 평균·중앙값·percent_rank를 계산하며 동률은 같은 백분위다. relative 모드는 시간 표본 10건 이상, 하위 10% 이하이면서 중앙값의 25% 미만일 때 빠른 신호를 준다. 표본이 부족하면 상대 판단을 보류한다. either 모드에서는 절대 기준을 사용할 수 있지만 상대 표본 부족 안내를 표시한다. 1시간 초과는 방치 가능성을 안내하고 가점을 주지 않는다.

품질 집계는 문항과 출석을 한 번에 JOIN하지 않는다. 먼저 응답당 점수 합/개수로 집계하고, 후속 출석은 EXISTS/프로그램 DISTINCT로 따로 계산한 후 응답 키로 JOIN한다. 원본·제외 평균은 점수 합/점수 개수로 계산해 문항 수 차이에도 기존 집계 의미를 유지한다. 0건은 NULL이고 0점으로 대체하지 않는다. 가중 평균은 정보 부족 응답에 w=1을 쓰는 중립 유지 정책으로, 품질이 높다는 추정과 구분한다.

화면과 리포트는 같은 PostgreSQL 함수를 사용한다. Python에는 별도 품질 판정 구현이나 결과 하드코딩이 없다. `load_analysis`는 READ ONLY + REPEATABLE READ 트랜잭션으로 카드/상세/출석/문항분류를 동일 스냅샷에서 읽는다.

## 합성 데이터와 실제 DB 결과

사용자의 localhost:5432 DB는 인증 정보가 제공되지 않아 직접 조회하지 못했다. 대신 PostgreSQL 16.15 서버 바이너리로 **127.0.0.1:55439 독립 클러스터**를 만들고, 원본 미션 2 SQL을 그대로 적용한 실제 PostgreSQL DB에서 검증했다. 아래 값은 이 복제 스키마·시드/합성 시연 DB의 실제 쿼리 결과이며 실제 학교 학생 운영 결과가 아니다. 원래 5432 DB에는 어떤 쓰기도 수행하지 않았다.

합성 참여는 개인 성향과 이전 내용 만족도에 따른 확률로 생성한다. 신청 기회, 실제 출석, 설문 작성 여부는 따로 생성한다. 높은 만족도·미재참여와 낮은 만족도·재참여를 모두 허용하며 특정 집계 차이를 강제하지 않았다. 합성 유형 레이블은 생성 가정이며 실제 학생 응답 품질의 정답이 아니다.

합성 시연의 전체 점수 평균은 **3.58244 → 의심 제외 3.57236**으로 차이가 작았다. 프로그램별 제외 평균은 **11개 상승, 13개 하락**, 변화 범위 약 **−0.18425~+0.18339점**이었다. 프로그램 01은 원본 3.66854, 제외 3.51370, 가중 3.52394이다. 프로그램 02는 3.60417 → 3.61919로 상승했다. “항상 부풀려진 만족도를 낮춘다”는 결론을 내릴 수 없다.

의심 제외 후 4점 이상 집단의 재참여율은 95.79%(관찰 665건), 3점 미만은 70.85%(관찰 470건)였다. 두 집단의 차이는 원본 약 28.23%p에서 제외 후 약 24.94%p로 **줄었다**. 품질 필터가 만족도와 행동의 관계를 더 선명하게 만든다고 주장할 수 없다. 관찰 가능한 프로그램 19개의 원본 만족도와 재참여율 순위 상관도 약 0.144로, 두 순위가 일치하지 않았다. 표본·프로그램 공급·관찰 구성의 영향을 함께 고려해야 한다.

## 민감도와 집단 제외율

시연 데이터에서 문항당 절대 기준을 1/2/3초로 바꿔도 절대 신호 의심은 441건으로 같았다. 빠른 시나리오가 0.25~0.875초/문항, 일반 시간이 4초 이상인 생성 가정의 영향이다. 임계값이 항상 무관하다는 뜻이 아니다. 상대 전용 및 both 모드에서는 209건, either에서는 441건이었다. 다른 시간 분포의 실제 데이터로 재검토해야 한다.

화면에서 속도 기준, 반복 최소 문항 수, 상대 기준 표본 수, 감점, 제외 경계를 모두 변경할 수 있다. 민감도 버튼은 절대 1/2/3초 × 모드 4종의 결과와 반복 감점 0/15/30의 가중 평균 변화를 제공한다. 전체 프로그램별 CSV에도 저장한다.

합성 학과·학년 조합의 기본 제외율은 SI_D0·1학년 23.96%, SI_D1·2학년 18.49%, SI_D2·3학년 18.66%, SI_D3·4학년 17.88%로 차이가 있었다. 합성 생성에서 학과·학년이 연동되어 있어 실제 집단 공정성을 검증한 결과로 해석할 수 없다. 과도한 제외 여부를 확인하는 진단 표이며, 향후 표본 구성과 응답 환경에 대한 점검이 필요하다.

## 선택적 머신러닝

Logistic Regression은 강사·내용·운영·시간의 실제 문항분류 평균만 입력으로 사용했다. 데이터가 충분한 합성 출처에서만 평가됐다. 학습/평가 학생을 SHA256 기반 분할로 분리하고, 학습의 90일 라벨이 확정된 뒤 평가 설문이 시작되게 purge했다. 단일 시점 holdout이며 교차 검증이나 실데이터 외부 검증은 아니다.

학습 554건, 평가 135건, 학생 중복 0명. 분리 시점은 2026-04-05 14:31:51+09, 마지막 학습 라벨 확정 14:30:00+09, 첫 평가 설문 14:33:00+09이다. 의심 제외 학습은 같은 평가 집합을 쓰고 학습만 455건으로 줄였다.

| 모델 | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| 다수 클래스 기준 | .8296 | .8296 | 1.0000 | .9069 | .5000 |
| Logistic | .8519 | .8594 | .9821 | .9167 | .8009 |
| 의심 제외 학습 Logistic | .8519 | .8594 | .9821 | .9167 | .8005 |

의심 제외가 예측 성능을 높이지 않았다. 반복 응답 간 상관과 재참여 양성 비율 약 83% 때문에 Accuracy만으로 성능을 판단하지 않는다. 내용 분류의 표준화 계수 절댓값이 약 1.451로 가장 컸고, 평가 집합 내용 점수를 ±0.5점 변경했을 때 평균 예측확률 변화는 +0.0475/−0.0595였다(1~5점 범위로 제한). **합성 생성기의 가정을 반영한 모델 민감도이며 실제 내용 개선 효과가 아니다.** 원본 미션 2 데이터는 출석 관찰 정보가 없어 모델 평가 불가로 출력했다.

## 발표 시연 절차 (약 6분)

1. **문제·사용자 (40초):** 담당자가 평균만으로 응답 근거를 알 수 없다는 문제를 설명한다. 미션 2 시드를 선택해 시작 시각 미측정 상태를 먼저 보여준다. 원본 DB 자료를 임의로 복원하지 않았음을 설명한다.
2. **시간·패턴 (70초):** 합성 시연 → 프로그램 01 → 응답 품질 탭에서 빠름+반복과 반복 단독을 비교한다. 25점 대 85점, 느린 5점 반복은 기본 제외하지 않는다는 것을 보여준다.
3. **집계 비교 (50초):** 만족도 현황에서 3.66854 → 3.51370을 확인하고, 프로그램 02에서는 제외 평균이 상승함을 보여준다. 보정값이 정답이 아니라 가정에 따른 비교값임을 설명한다.
4. **민감도 (50초):** 절대/상대 기준 및 제외 경계를 바꾸고 근거·제외 수·평균이 함께 달라짐을 보여준다. 1~3초에 변화가 없으면 합성 시간 분포의 간격 때문이라고 설명한다.
5. **실제 행동 연결 (70초):** 재참여 탭의 실제 출석과 관찰 상태를 확인한다. 관찰 기간 부족/기회 없음은 미재참여로 처리하지 않음을 설명한다. 만족도 구간별 제외 전후 표와 프로그램 산점도로 관계를 비교한다.
6. **가치·발전 (60초):** 관리자에게 확정 판정 대신 근거와 불확실성을 제공한다고 설명한다. 선택적으로 모델 평가 버튼을 눌러 기준 모델·학생 분리·성능 개선이 없었던 사실을 확인한다. 최종 서비스 계획을 제시한다.
