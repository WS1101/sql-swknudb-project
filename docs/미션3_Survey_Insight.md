# Survey Insight — 설문 품질 기본판

팀 공통 참여 구조를 기다리는 동안 독립적으로 개발·시연할 수 있도록 정리한 현재 버전이다. 분리 전 전체 구현의 결과·모델 검증은 [이전 확장판 기록](archive/미션3_Survey_Insight_확장판_검증기록.md)에 보관했다.

## 문제·사용자·요구사항

대상은 SW중심대학사업 프로그램 담당자다. 평균만으로는 응답 근거를 알기 어려우므로 시간·반복 점수 신호로 원본과 의심 제외 평균을 비교한다. 불성실함을 확정하거나 원본을 삭제하지 않는다.

실제 과제 DOCX는 기존 DB를 활용한 핵심 프로토타입, 사용자/문제 정의, 구현 범위와 발전 계획을 요구한다. 가상 데이터를 허용하며 이번 단계에서 공개 배포는 요구하지 않는다. 기본판은 설문 품질이라는 한 가지 핵심에 집중한다.

## DB 구조와 연결 경계

기존 상세는 `(response_id,question_id)`로 응답/문항을 연결한다. `student_no`와 응답 당시 학과·학년 스냅샷이 있다. 제출 `responded_at`만 있어 과거 시간은 미측정으로 유지한다. 문항분류는 기존 category_code를 쓰고 내용/운영/전반 만족을 강사/시간으로 임의 재분류하지 않는다. 최신 완료 응답은 기존 `analytics.v_survey_response_final`을 재사용한다.

`10`이 추가하는 테이블은 analytics 설정·시작 시각 관측·합성 프로그램 구분 3개다. 프로그램 메타데이터/응답별 기초/문항분류 뷰와 시간 검증/품질/평균 함수를 둔다. public 참여 테이블은 만들지 않는다. 기존 컬럼과 응답 데이터는 변경하지 않는다.

기존 버전에 재적용할 수 있도록 프로그램 뷰/요약 함수의 `attendance_count`는 NULL 호환 자리로 유지했다. 출석 참조가 없고 기본 UI에도 표시하지 않는다. 이미 만든 출석 테이블과 데이터는 삭제하지 않는다.

양쪽 시간 갱신 경로에서 시작≤제출을 검증한다. 미션 2의 점수 범위·유형·조사 일치·완료 보호는 유지한다. 함수는 고정 search_path와 최소 조회 권한, 앱은 READ ONLY + REPEATABLE READ를 사용한다. 학생 식별자는 세션별 HMAC 가명으로만 표시한다.

우진이의 참여자/회차/시간표 구조는 기본판에서 참조하지 않는다. 테이블 확정 후 `analytics.v_attendance_event(student_no,program_id,attended_at)`의 SELECT만 실제 JOIN으로 연결한다. 여러 회차는 여러 행을 유지하고 학생 수 집계에서 중복을 제거한다.

선택 `06`/`11`은 빈 연결 VIEW·연결 플래그·관찰 수집 범위·후속 분석을 제공한다. 처음은 출석 연계 대기, 출석만 연결되면 참여 기회 연계 대기이다. 정보 부족을 0명/미재참여로 표시하지 않는다. 재적용해도 매핑을 덮어쓰지 않는다. [연결 계약](참여데이터_연결계약.md)에 합의할 항목을 정리했다.

## 규칙과 시연 결과

기본 지표는 `max(0,100 − 빠름×40 − 반복×15 − 동시발생×20)`, 제외 경계는 70 미만이다. 느린 반복 85와 빠른 반복 25를 구분한다. 시간/문항/상대 표본이 부족하면 별도 상태와 NULL 지표다. 확률이나 검증된 불성실 판정이 아니며 설정은 시연용 가설이다.

원본/제외 평균은 점수 합/개수, 분모가 없으면 NULL이다. 가중 평균은 보조 분석이며 정보 부족은 중립 유지 정책으로 w=1이다. 점수는 응답별로 먼저 집계해 JOIN 중복을 방지한다.

독립 PostgreSQL 16.15에 기존 SQL을 적용했다. 원래 5432 DB 인증 정보가 없어 그 DB를 직접 검증한 결과는 아니다. 기존 시드의 최신 완료 128건은 시작 시각과 충분한 문항 수가 없어 정보 부족으로 유지한다.

합성 시드는 학생 360명·프로그램 24개·응답 2,377건이다. 미완료 136건 제외 후 2,241건 중 기본 의심 441, 정보 부족 262건이다. 원본 전체 약 3.58244, 제외 약 3.57236이며 프로그램별 상승 11개·하락 13개다. 특정 결과를 강제하지 않았다. **기본 시드는 출석 레코드를 저장하지 않으므로 재참여율을 주장하지 않는다.**

## 검증 결과

| 검증 | 결과 |
|---|---|
| 출석/기회 테이블·후속 함수 없이 05만 설치 | 성공 |
| 기본 SQL·기본 합성 시드·기본 대시보드 | 22 tests passed |
| 매핑 교체·회차 중복·연계 상태·재참여·선택 모델 | 7 tests passed |
| 기본 DB / 선택 DB 각각 미션 2 T01~T13 | 각 PASS 154 + NOTICE PASS 31, FAIL 0 |

기본 테스트는 빠른/느린 반복, 정상/미측정/미완료/최신 완료, 시간 통계·분산·동률, 소표본·임계값, 수작업 평균, 빈 집계·모두 제외·0 가중치, 양방향 시간, DB–화면 일치, reader 권한, 세 탭과 설정 변경을 검증한다.

선택 테스트는 다른 이벤트 테이블로 VIEW를 교체해 같은 분석이 동작하는지 확인한다. 중복/다회차가 인원수·재참여를 부풀리지 않는지, 연결 미완료를 음성으로 오인하지 않는지, 90일 경계·과거·동시·같은 프로그램·관찰 부족·기회 없음과 매핑 보존을 검증한다. 모델은 시간/학생 분리와 라벨 성숙 조건을 검증한다.

전용 `_test` DB에서 실행하고 fixture는 롤백한다. [실행 안내](../analysis/README.md)에 기본/선택 테스트와 설치 명령을 분리했다. 이전 전체 버전의 데이터는 자동 삭제하지 않는다.

## 발표 순서·발전 계획

1. 기존 시드의 평균과 시간 정보 없음을 보여준다. 없는 시간을 복원하지 않았다고 설명한다.
2. 합성 응답의 빠른/느린 반복과 근거·지표 차이를 보여준다.
3. 원본/제외 평균과 프로그램마다 다른 변화 방향을 확인한다.
4. 임계값 민감도를 보여주고 보정값도 정답은 아니라고 설명한다.
5. 기본판은 설문만으로 동작하고 공통 참여 구조는 VIEW로 연결한다는 분담을 설명한다.

다음은 키·실제 출석·회차 시각·완료 기준 합의 → 연결 VIEW → 실제 참여 기회/수집 범위 확인 → 90일 재참여/선택 모델 활성화 순서다. 이후 시작 이벤트 API, 현장 기준 검증, 로그인·권한·백업·운영 배포를 진행한다.

현재 미구현/미확정: 실제 학교 출석 연동, 팀 공통 컬럼 매핑, 실제 참여 기회·관찰 구간, 학생 설문 입력 API, 실제 응답 품질 정답 검증, 웹 로그인/RLS·운영 배포. 기본 기능과 선택 확장을 명확히 구분한다.
