# 개발 Seed 데이터

## 구현 기준

이 프로젝트는 애플리케이션 ORM이나 별도 마이그레이션 프레임워크 없이 PostgreSQL DDL과 `psql`의 `\ir` 명령으로 스키마와 데이터를 관리한다. 실행 순서는 `01_schema.sql`과 `02_seed.sql`에 고정되어 있다. PostgreSQL 16에서 검증했으며 `pgcrypto`, 범위형, GiST exclusion constraint, PL/pgSQL 트리거와 업무 함수를 사용한다.

Seed는 기존 스키마와 업무 함수를 변경하지 않는다. 고정 코드와 자연 업무키를 먼저 조회하고, 없을 때만 추가하며, 같은 키에 다른 내용이 있으면 기존 행을 수정하지 않고 예외로 중단한다. 각 파일은 트랜잭션과 advisory lock을 사용하므로 중간 실패 시 해당 도메인의 입력 전체가 롤백된다.

삽입 순서는 다음 FK 의존 관계를 따른다.

1. 사용자·관리자·역할·권한
2. 대학·캠퍼스·학과·교수·예산항목 등 기준정보
3. 학생과 학생정보 수정 요청
4. TOPCIT 회차·점수·마일리지 기준
5. 프로그램·마일리지 신청·첨부
6. 사업·최초예산·지출
7. 만족도 조사·문항·응답
8. 관계와 집계값 검증

## 데이터 구성

| 구분 | 건수 | 내용 |
|---|---:|---|
| 사용자 | 35 | 학생 32, 마스터 관리자 1, 일반 관리자 2 |
| 학생 | 32 | 4개 학과, 1~4학년, 재학 28·휴학 4 |
| 학생정보 수정 요청 | 10 | 승인 4·대기 3·반려 3 |
| 교수 | 4 | 학과별 가상 교수와 교번 |
| TOPCIT 회차 / 점수 | 4 / 110 | 학생 32명 모두 다회차 이력, 점수 정정 이력 4건 |
| 프로그램 / 마일리지 기준 | 10 / 10 | 경진대회·교육·캠프·멘토링, 참여·입상 기준 |
| 마일리지 신청 / 첨부 | 84 / 84 | 승인 31·취소 15·대기 15·반려 19·회수 4 |
| 예산사업 / 최초예산 | 2 / 14 | 2025·2026 사업, 사업별 7개 예산항목 |
| 지출 | 42 | 승인 20·대기 14·반려 8, 교수·지출주체·프로그램 연결 |
| 만족도 조사 / 문항 | 6 / 24 | 조사별 5점 척도 3문항과 주관식 1문항 |
| 만족도 응답 / 상세 | 129 / 516 | 4개 학과와 1~4학년, 재응답 사례 포함 |
| Seed 변경 로그 | 305 | 학생정보·TOPCIT·마일리지·예산·지출 처리 이력 |

모든 이름, 전화번호, 이메일, 파일 경로는 가상 값이다. 계정 비밀번호는 `pgcrypto.crypt(..., gen_salt('bf'))`로 생성한 bcrypt 해시이며 복구 가능한 공통 비밀번호를 두지 않는다.

## 실행

빈 로컬 DB를 스키마부터 다시 만들 때만 다음 명령을 사용한다. `reset.sql`은 `public` 스키마를 삭제한다.

```bash
psql -U postgres -d swknu_db \
  -v seed_environment=development \
  -v reset_confirm=RESET_LOCAL_DB \
  -f reset.sql
```

이미 스키마가 있는 개발 DB에는 다음 명령으로 Seed만 추가하거나 재검증한다. 일반 사용자 행과 운영 데이터는 삭제하거나 갱신하지 않는다.

```bash
psql -U postgres -d swknu_db \
  -v seed_environment=development \
  -f 02_seed.sql
```

`seed_environment`는 `development`, `test`, `local`만 허용한다. 데이터베이스 이름에 `prod` 또는 `production` 구분자가 있으면 실행을 거부한다. 별도 검증은 다음과 같이 다시 실행할 수 있다.

```bash
psql -U postgres -d swknu_db -f tests/T12_seed_integrity.sql
```

Seed만 선택 삭제하는 스크립트는 제공하지 않는다. `change_log`가 UPDATE와 DELETE를 막는 불변 감사 로그이고 업무 이력의 임의 삭제는 현재 설계 원칙에 어긋나기 때문이다. 완전 초기화가 필요하면 위의 보호된 `reset.sql`을 로컬 전용 DB에서 실행한다.

## 검증 항목

`seed/08_verify.sql`은 다음 조건이 하나라도 맞지 않으면 예외를 발생시킨다.

- 학생·회차별 TOPCIT 점수의 유일성과 전 학생 다회차 이력
- 승인 상태 마일리지의 합과 `student.cumulative_mileage`의 일치
- 마일리지의 대기·승인·반려·취소·회수 상태 존재
- 승인 지출 합계가 항목별 지출한도 이하이며 잔액이 음수가 아님
- 만족도 완료 응답이 조사별 네 문항에 모두 답했고 문항 유형과 답변 유형이 일치함
- 변경 로그 처리자가 실제 `app_user`를 참조하며 각 도메인의 처리 이력이 존재함

PostgreSQL 16 임시 클러스터에서 전체 초기화 후 Seed를 두 번 연속 실행했다. 두 실행 모두 제약조건 오류 없이 통과했고 두 번째 실행 뒤에도 모든 건수가 동일했다. 승인 마일리지 합계와 학생 누적값은 각각 2,475점, 전체 지출한도·승인지출·잔액은 각각 1,217,000,000원·108,850,000원·1,108,150,000원으로 일치했다. 기존 마일리지·지출 승인 회귀 테스트와 `T12_seed_integrity.sql`도 통과했다.

## 현재 스키마에서 표현하지 못하는 범위

- `app_user.user_type`은 `STUDENT`와 `ADMIN`만 허용하고 `professor`는 독립 기준정보이므로 교수 로그인 계정과 역할 연결은 만들지 않았다.
- 예산 잔액과 누적 지출액 컬럼은 없다. 승인 상태 지출만 합산해 조회 시 계산한다.
- 만족도 조사에는 프로그램 참여자 테이블이 없어 프로그램 참여 여부와 설문 응답 자격을 DB FK로 연결할 수 없다.
- 만족도 응답은 학생·조사별 중복을 허용하는 설계다. 재응답 사례를 포함했고 통계에서는 최신 완료 응답을 선택해야 한다.
- 지출 상태에는 `CANCELLED`가 있지만 취소 업무 함수와 취소 처리자·일시 컬럼이 없어 Seed에는 임의의 취소 지출을 만들지 않았다.
- `change_log.target_id`는 여러 테이블의 문자·숫자 PK를 함께 담는 다형 참조라 대상 행에 대한 FK는 없고, 처리자만 `app_user` FK로 보장한다.
